# SavorSeek 用户流程文档

## 一、文档说明

### 1.1 文档目的

本文档把 [`PRD.md`](PRD.md) 中的功能需求组织为端到端的用户流程，明确页面职责、导航关系、状态流转、分支与异常路径，作为客户端交互设计、Agent 状态展示和端到端测试用例设计的依据。

本文档描述**用户如何走完一件事**，不规定视觉设计与实现方案。

### 1.2 关联文档

| 文档 | 关系 |
|------|------|
| [`PRD.md`](PRD.md) | 上游：功能需求（FR）与非功能需求（NFR）来源 |
| [`验收标准.md`](验收标准.md) | 下游：本文档的流程步骤转换为可执行验收条件 |
| [`docs/项目计划书.md`](../项目计划书.md) | 上游：交互原则与主要页面定义 |

### 1.3 编号规则

- 主流程：`UF-<两位序号>`。
- 流程步骤：`UF-xx.<序号>`。
- 分支与异常：`UF-xx.E<序号>`。

编号在 [`验收标准.md`](验收标准.md) 中被引用，发布后不复用。

### 1.4 图示约定

本文档使用文本流程图，约定如下：

```text
[页面]        用户可见的页面或视图
(动作)        用户操作
<系统>        系统或 Agent 行为
{判断}        分支条件
=>            正常流转
!!            异常或降级流转
```

## 二、信息架构

### 2.1 页面清单

| 页面 | 标识 | 职责 | 主要需求 |
|------|------|------|----------|
| 地图页 | P-MAP | 主工作区：地图、搜索、筛选、结果列表、需求输入入口 | FR-201~FR-205、FR-211~FR-213 |
| 地点详情页 | P-PLACE | 单个地点的完整信息、来源标注、收藏与加入行程 | FR-206~FR-210、FR-401~FR-404 |
| 需求确认面板 | P-INTENT | 回显结构化需求，允许逐项修改后执行 | FR-501~FR-503 |
| Agent 工作室页 | P-STUDIO | 任务状态、输入输出摘要、依赖关系、取消与重跑 | FR-504~FR-512 |
| 推荐结果页 | P-REC | 候选列表、理由、风险提示、操作入口 | FR-601~FR-609 |
| 行程页 | P-TRIP | 时间表与地图路线双视图、节点编辑、冲突提示 | FR-701~FR-710 |
| 个人偏好页 | P-PREF | 记忆清单、编辑删除、隐私设置、数据删除 | FR-103~FR-104、FR-301~FR-310 |
| 收藏与历史页 | P-LIB | 收藏地点、已去过、历史行程、我的反馈与纠错 | FR-207、FR-806、FR-709 |
| 登录页 | P-AUTH | 注册、登录、登出 | FR-101~FR-102、FR-105 |

### 2.2 导航结构

```text
[P-AUTH]
   => 登录成功 => [P-MAP]（默认首页，底部主导航）

底部主导航（四个入口）
   ├── [P-MAP]    地图
   ├── [P-TRIP]   行程
   ├── [P-LIB]    收藏与历史
   └── [P-PREF]   我的偏好

从 [P-MAP] 可进入
   ├── [P-PLACE]   点击地图标记或结果列表项
   ├── [P-INTENT]  提交自然语言需求后
   └── [P-STUDIO]  需求执行中，或点击状态条

从 [P-STUDIO] 可进入
   ├── [P-REC]     推荐任务完成
   └── [P-TRIP]    路线任务完成

从 [P-REC] 可进入
   ├── [P-PLACE]   查看候选详情
   └── [P-TRIP]    加入行程后查看
```

导航约束：

1. 地图页是唯一的默认首页；推荐与行程均从地图页发起或回到地图页确认（PRD 产品原则「地图优先」）。
2. `P-STUDIO` 不阻断导航；用户在任务执行中可离开去浏览地图，返回后状态保持。
3. `P-PLACE` 可从地图、结果列表、推荐结果、行程节点四处进入，返回时回到来源页面并保留原有滚动与筛选状态。

### 2.3 全局状态

| 状态 | 取值 | 影响 |
|------|------|------|
| 登录态 | 已登录 / 未登录 | 未登录时推荐、记忆、行程入口引导登录（FR-105） |
| 定位态 | 可用 / 拒绝 / 失败 | 不可用时回退默认城市并提示（NFR-201） |
| 网络态 | 在线 / 离线 | 离线时展示缓存数据并标注（NFR-202） |
| 会话态 | 无会话 / 执行中 / 已完成 / 已取消 / 已失败 | 决定状态条与 `P-STUDIO` 呈现 |
| 偏好加权 | 开启 / 关闭 | 影响排序与排序说明（FR-212、FR-609） |

## 三、核心流程

### UF-01 首次启动、授权与账户初始化

**目标**：新用户在最少步骤内完成登录、必要授权与基础偏好设置，并明确知道系统将记录什么。

**前置条件**：应用首次安装启动。

**主路径**

```text
UF-01.1  [启动] <展示产品定位与隐私说明摘要>
UF-01.2  <说明将记录哪些偏好、用途与关闭方式>（PRD 8.2 第 1 条）
UF-01.3  (选择注册或登录) => [P-AUTH]
UF-01.4  <Supabase Auth 完成认证> => 建立登录态（FR-101）
UF-01.5  <按需申请位置权限，说明用途>（PRD 8.2 第 2 条）
UF-01.6  {是否授权定位}
           授权   => UF-01.7
           拒绝   => UF-01.E1
UF-01.7  [基础设置] (设置默认城市、人均预算区间、交通方式、忌口清单)（FR-103）
UF-01.8  <忌口写入为明示记忆，标记为硬性约束>（FR-302、FR-308）
UF-01.9  (可跳过设置) => [P-MAP] 定位到当前位置，展示视野内地点
```

**分支与异常**

| 编号 | 情况 | 处理 |
|------|------|------|
| UF-01.E1 | 用户拒绝定位 | 提供手动选择城市入口，回退到默认城市，不重复弹窗（NFR-201、PRD 8.2 第 2 条） |
| UF-01.E2 | 认证失败（网络或凭据错误） | 区分「网络不可用」与「账号密码错误」提示，保留已输入内容 |
| UF-01.E3 | 用户跳过基础设置 | 进入地图页；首次发起推荐时集中追问关键约束（FR-503） |
| UF-01.E4 | 未登录浏览 | 允许浏览地图与地点详情；触发推荐、收藏、行程时引导登录并在登录后回到原操作（FR-105） |

**完成判据**：用户处于已登录态，位于 `P-MAP`，且系统已明确告知偏好记录规则。

### UF-02 地图探索与地点查看

**目标**：用户在不使用对话的情况下，通过地图与筛选自主发现地点并完成收藏或加入行程。

**前置条件**：位于 `P-MAP`。

**主路径**

```text
UF-02.1  [P-MAP] <展示视野内地点标记，密集处聚合>（FR-201、FR-202）
UF-02.2  (缩放/平移) => <按视野重新加载标记，不阻塞交互>（NFR-106）
UF-02.3  (输入关键词搜索) => <结果同时更新地图与列表>（FR-203、FR-205）
UF-02.4  (设置筛选：菜系/价格/距离/评分/营业状态/特色标签)（FR-204）
UF-02.5  {结果是否为空}
           非空 => UF-02.6
           空   => UF-02.E1
UF-02.6  (切换列表视图) => <展示与地图等价的卡片列表>（FR-205、NFR-301）
UF-02.7  (点击标记或列表项) => [P-PLACE]
UF-02.8  [P-PLACE] <展示基础信息、特色菜品、评价摘要、内容提及>（FR-206）
UF-02.9  <标注每条外部信息的来源与信息层级>（FR-401、FR-402）
UF-02.10 <标注易变字段的更新时间；缺失时显示「更新时间未知」>（FR-209）
UF-02.11 <对过期、单一来源、疑似推广信息给出提示>（FR-403、FR-404）
UF-02.12 (选择操作)
           (收藏 / 标记已去过 / 标记明确喜欢或不喜欢 / 添加备注)
              => <写入并即时反馈>（FR-207）
           (加入行程) => 选择日期与时段 => [P-TRIP] 或原地确认（FR-208）
           (查看来源) => <跳转出处或展示出处信息>（FR-401）
UF-02.13 (返回) => 回到来源页面，保留筛选与滚动位置
```

**可选分支**

| 编号 | 情况 | 处理 |
|------|------|------|
| UF-02.A1 | 地点对比（P1） | 选择 2~4 个地点进入对比视图，对比价格、距离、评分、特色、排队风险（FR-210） |
| UF-02.A2 | 区域框选探索（P1） | 在地图框选区域后交给 Agent 仅探索该区域，转入 UF-03.4（FR-211） |
| UF-02.A3 | 偏好加权展示（P1） | 已有记忆时按偏好匹配度排序，并显式说明排序受偏好影响，可关闭（FR-212、FR-609） |
| UF-02.A4 | 区域热度展示（P1） | 按区域展示美食密度或热度分布，并说明热度口径与数据来源（FR-213） |

**分支与异常**

| 编号 | 情况 | 处理 |
|------|------|------|
| UF-02.E1 | 筛选结果为空 | 说明是哪些筛选条件导致为空，提供逐项放宽入口，不返回无解释空白页 |
| UF-02.E2 | 离线或网络异常 | 展示缓存地点并标注为缓存数据；禁用需要联网的操作并说明原因（NFR-202、NFR-206） |
| UF-02.E3 | 地图服务不可用 | 保留列表视图与已保存行程查看能力，提示地图暂不可用（NFR-203） |
| UF-02.E4 | 地点详情部分字段缺失 | 缺失字段显示为「暂无信息」，不用占位数据或推断值填充（AB-01、AB-02） |

**完成判据**：用户完成至少一次收藏或加入行程操作，且所见外部信息均带来源与时效标注。

### UF-03 对话式需求表达与推荐生成

**目标**：用户用自然语言表达需求，确认结构化解析结果，观察 Agent 执行过程，得到可解释、可操作的推荐。

**前置条件**：已登录，位于 `P-MAP`。

**主路径**

```text
UF-03.1  [P-MAP] (输入自然语言需求)
           例：「今天住在这附近，想吃本地菜，每人 150 元，不去连锁店」
UF-03.2  <解析为结构化需求：区域/时间窗/人数/预算/菜系/忌口/交通/其他约束>（FR-501）
UF-03.3  [P-INTENT] <回显解析结果，逐项可修改>（FR-502）
UF-03.4  {关键约束是否缺失}
           缺失 => UF-03.E1（集中追问一轮）
           完整 => UF-03.5
UF-03.5  <未指定字段使用默认值，并标明默认来源（个人设置/系统默认）>（FR-503）
UF-03.6  (确认执行) => <创建会话，进入执行中>
UF-03.7  [P-STUDIO] <1 秒内出现任务状态>（NFR-103）
UF-03.8  <按八个阶段推进并展示状态：
            理解需求 => 检索候选 => 研究内容 => 读取偏好 => 核验信息
            => 排序推荐 => 生成路线 => 汇总结果>（FR-504）
           说明：八个阶段与项目计划书 6.4 节的八类 Agent 职责一一对应
UF-03.9  <每阶段展示关键输入与输出摘要及来源，不暴露多余思维链>（FR-505、AB-09）
UF-03.10 <淘汰违反硬性约束的候选：忌口、预算上限、时间窗、区域、开放状态>（FR-601）
UF-03.11 <推测记忆仅参与排序，不淘汰候选>（FR-307）
UF-03.12 {是否存在满足硬性约束的候选}
           有 => UF-03.13
           无 => UF-03.E2
UF-03.13 [P-REC] <展示候选，默认不超过 8 个>（FR-607）
UF-03.14 <每个候选给出理由：命中的需求项、偏好项与依据来源>（FR-603）
UF-03.15 <标注已知风险：营业时间不确定/排队风险/信息过期/来源单一>（FR-604）
UF-03.16 (对候选操作)
           (收藏) / (加入行程) / (查看来源) / (替换候选)（FR-605）
           (查看详情) => [P-PLACE]
UF-03.17 {是否继续规划路线}
           是 => UF-04
           否 => 结束会话
```

**分支与异常**

| 编号 | 情况 | 处理 |
|------|------|------|
| UF-03.E1 | 关键约束缺失 | 集中追问一轮（最多一轮），其余字段用默认值并标明来源；用户可跳过追问（FR-503、AB-08） |
| UF-03.E2 | 无候选满足硬性约束 | 指出冲突的具体约束项，给出可选放宽建议，等待用户决定；禁止静默放宽或返回空列表（FR-606、AB-04） |
| UF-03.E3 | 单个任务失败 | 汇总其余任务的可用产出，标注结果不完整与失败环节（FR-507、AB-06） |
| UF-03.E4 | Agent 超时 | 达到超时与重试上限后返回失败原因与降级结果，降级结果显式标注（FR-506、NFR-205、NFR-206） |
| UF-03.E5 | 内容来源不可用 | 「研究内容」阶段状态置为「跳过」并说明原因，基于地点数据与偏好完成推荐，标注信息维度不完整（NFR-204、FR-504） |
| UF-03.E6 | 用户取消 | 立即停止；不写入记忆、不修改行程（FR-508） |
| UF-03.E7 | 成本上限触顶 | 停止执行并告知用户已达上限，保留已产出的部分结果（FR-510） |
| UF-03.E8 | 修改约束后重跑 | 仅重跑受影响任务，保留未受影响的产出（FR-511，P1） |
| UF-03.E9 | 请求超出产品范围 | 明确拒绝医疗、营养诊断类请求，说明能力边界（AB-07、NFR-509） |

**完成判据**：推荐结果带理由、来源与风险提示，硬性约束零违反，且用户可对结果执行至少一种操作。

### UF-04 一日美食路线规划

**目标**：把候选地点组织为符合时间、距离、营业时间与预算约束的当日路线。

**前置条件**：已有推荐结果或已收藏地点；已确定时间窗。

**主路径**

```text
UF-04.1  (发起路线规划) 入口：[P-REC] 或 [P-TRIP] 或对话
           例：「上午十点到晚上八点，中间留出休息和交通时间」
UF-04.2  <确认时间窗、出发点、交通方式、人均预算>（沿用 UF-03 结构化需求）
UF-04.3  [P-STUDIO] <展示「生成路线」阶段状态>（FR-504）
UF-04.4  <依据时间窗、营业时间、地点距离、停留时长、预算生成顺序>（FR-703）
UF-04.5  <按日期与时段组织节点：上午/午餐/下午茶/晚餐/夜宵>（FR-701）
UF-04.6  <每个节点记录地点、预计到达、停留时长、预算、备注>（FR-702）
UF-04.7  [P-TRIP] <时间表视图与地图路线视图并存且一致>（FR-704）
UF-04.8  <标注通行时间为规划参考，不替代专业导航>（PRD 10.1）
UF-04.9  {是否存在冲突}
           有 => UF-04.E1
           无 => UF-04.10
UF-04.10 (保存行程) => <保存并可在重启后恢复>（FR-708）
```

**分支与异常**

| 编号 | 情况 | 处理 |
|------|------|------|
| UF-04.E1 | 存在冲突（营业时间冲突、通行时间不足、预算超限、排队风险） | 明确提示冲突项与修复建议，允许用户选择修复方式（FR-706） |
| UF-04.E2 | 路线服务不可用 | 用直线距离估算通行时间，并标注为粗略估计（PRD 10.1） |
| UF-04.E3 | 时间窗内无法容纳全部选定地点 | 说明超出的节点与原因，提供删减或延长时间窗建议，不静默丢弃节点 |
| UF-04.E4 | 地点营业时间未知 | 标注不确定，不假定营业，并提示需自行确认（AB-02、AB-10） |

**完成判据**：行程可保存并恢复，地图与时间表一致，冲突项均有提示。

### UF-05 行程调整与重新规划

**目标**：用户调整行程后，系统在不破坏用户决定的前提下重算后续安排。

**前置条件**：位于 `P-TRIP`，已有已保存行程。

**主路径**

```text
UF-05.1  [P-TRIP] (选择调整方式)
           (新增节点) / (替换地点) / (删除节点)
           (调整顺序) / (修改时间或停留时长)（FR-705）
UF-05.2  (可选：锁定不希望被修改的节点)（FR-707）
UF-05.3  <重算后续节点的预计到达时间与顺序>（FR-705）
UF-05.4  <重算与界面更新在 2 秒内完成>（NFR-105）
UF-05.5  <地图路线与时间表同步更新，保持一致>（FR-704）
UF-05.6  {锁定条件下是否可满足约束}
           可以   => UF-05.7
           不可以 => UF-05.E1
UF-05.7  {是否产生新冲突}
           是 => 展示冲突与修复建议（FR-706）
           否 => UF-05.8
UF-05.8  <保存变更；高影响变更提供撤销入口>（FR-708、FR-509）
```

**分支与异常**

| 编号 | 情况 | 处理 |
|------|------|------|
| UF-05.E1 | 锁定节点导致无解 | 报告冲突并说明是哪个锁定节点造成，等待用户决定是否解锁；禁止自动解锁或修改锁定节点（FR-707、AB-04） |
| UF-05.E2 | 替换候选不足 | 说明可替换候选不足的原因（区域、时段、约束），提供放宽建议 |
| UF-05.E3 | 重算失败 | 保留调整前的行程状态，提示失败原因，不产生半成品行程（AB-06） |
| UF-05.A1 | 多草稿（P1） | 保存多个草稿并切换查看，切换不影响其他草稿（FR-709） |
| UF-05.A2 | 导出（P1） | 导出为便于查看的清单形式（FR-710） |

**完成判据**：调整后行程一致、无未提示的冲突、锁定节点未被修改。

### UF-06 反馈与纠错

**目标**：用户纠正推荐与信息错误，并清楚知道该操作是否影响长期记忆。

**前置条件**：存在推荐结果或地点详情。

**主路径**

```text
UF-06.1  (在 [P-REC] 或 [P-PLACE] 发起反馈)
UF-06.2  {反馈类型}
           推荐反馈 => UF-06.3（喜欢 / 不感兴趣 / 不准确）（FR-801）
           信息纠错 => UF-06.6（营业时间 / 菜品 / 价格 / 位置）（FR-802）
UF-06.3  <提交前告知该反馈是否影响长期记忆及影响方式>（FR-803、AB-05）
UF-06.4  <当前会话排序即时生效>（FR-804）
UF-06.5  {是否升级为长期记忆}
           是 => 需用户明确确认后写入，并提供撤销（FR-306、FR-803）
           否 => 仅作用于当前会话
UF-06.6  <纠错记录与地点关联保存>（FR-802）
UF-06.7  <反馈提交结果即时可见>
UF-06.8  (可选) [P-LIB] <查看已提交的纠错记录与处理状态>（FR-806，P1）
```

**分支与异常**

| 编号 | 情况 | 处理 |
|------|------|------|
| UF-06.E1 | 提交失败（网络异常） | 保留用户输入，提供重试；不丢失内容 |
| UF-06.E2 | 用户拒绝写入长期记忆 | 仅在当前会话生效，不写入任何记忆条目（FR-309） |
| UF-06.E3 | 主动询问反馈 | 同一会话内不重复询问，用户可关闭主动询问（FR-805、AB-08，P1） |

**完成判据**：反馈已生效于当前会话，且长期记忆的写入与否与用户选择一致。

### UF-07 偏好与隐私管理

**目标**：用户完整查看系统记住了什么，并能修改、删除或清空。

**前置条件**：已登录，位于 `P-PREF`。

**主路径**

```text
UF-07.1  [P-PREF] <按类型分组列出全部记忆条目>（FR-304）
UF-07.2  <每条展示：值、来源（明示/推测）、置信度、更新时间、关联证据>（FR-301）
UF-07.3  <推测记忆显著标记为「系统推测」>（FR-303）
UF-07.4  (选择操作)
           (编辑值)（FR-305）
           (将推测记忆确认为明示记忆)（FR-305）
           (删除单条)（FR-305）
           (清空全部记忆) => 二次确认（FR-104、FR-305）
UF-07.5  <删除为真实删除；派生数据随之失效，不再影响推荐>（PRD 8.2 第 3、4 条）
UF-07.6  (查看隐私说明) <说明记录范围、用途、关闭方式>（FR-104）
UF-07.7  (调整基础设置：默认城市/预算/交通方式/忌口)（FR-103）
UF-07.8  <忌口变更后，后续推荐一律按硬性约束处理>（FR-308）
UF-07.9  (可选) (删除账户数据) => 二次确认 => <真实删除>（FR-104）
```

**分支与异常**

| 编号 | 情况 | 处理 |
|------|------|------|
| UF-07.E1 | 明示记忆之间冲突 | 向用户确认保留哪一条，不静默覆盖（FR-310） |
| UF-07.E2 | 新信息与推测记忆冲突 | 明示记忆优先；更新推测记忆并保留可见的更新时间（FR-310） |
| UF-07.E3 | 系统写入记忆 | 用户可感知，并提供撤销入口（FR-306、AB-05） |
| UF-07.E4 | 删除操作失败 | 明确告知未删除成功，不显示虚假成功状态（AB-06） |
| UF-07.E5 | 关闭偏好加权 | 排序不再使用软性偏好，硬性约束仍生效（FR-609） |

**完成判据**：用户可见的记忆清单与服务端一致，删除操作真实生效。

### UF-08 异常、降级与跨流程恢复

**目标**：在依赖不可用时，用户仍能得到可操作、已标注局限的结果，而不是空白或误导性结论。

**触发条件**：任一外部依赖异常或权限缺失。

**降级矩阵**

| 触发情况 | 保留能力 | 受限能力 | 用户提示 | 依据 |
|----------|----------|----------|----------|------|
| 定位失败或被拒绝 | 手动选择城市、地图浏览、搜索 | 基于当前位置的距离排序 | 提示定位不可用与替代方式 | NFR-201 |
| 网络离线 | 缓存地点浏览、已保存行程查看 | 搜索、推荐、行程保存 | 标注缓存数据，禁用联网操作并说明 | NFR-202、NFR-206 |
| 地图服务不可用 | 列表视图、已保存行程查看 | 地图标记、框选探索 | 提示地图暂不可用 | NFR-203 |
| 路线服务不可用 | 路线生成（直线估算） | 精确通行时间 | 标注为粗略估计 | UF-04.E2、PRD 10.1 |
| 内容来源不可用 | 基于地点数据与偏好的推荐 | 探店信息、特色描述 | 标注信息维度不完整 | NFR-204 |
| LLM 服务不可用 | 搜索、筛选、收藏、手动行程编辑 | 需求解析、推荐、摘要 | 说明智能能力暂不可用 | PRD 10.1 |
| Supabase 不可用 | 本地缓存查看 | 登录、写入、同步 | 明确错误提示 | PRD 10.1 |
| Agent 超时或失败 | 已完成任务的产出 | 未完成阶段的结论 | 标注结果不完整与失败环节 | FR-506、FR-507、NFR-205 |
| 成本上限触顶 | 已产出的部分结果 | 继续执行 | 告知已达上限 | FR-510 |

**恢复约束**

1. 降级结果必须显式标注，不得与正常结果混同（NFR-206）。
2. 恢复联网或依赖可用后，允许用户一键重试原请求，不需重新输入需求。
3. 异常期间不写入记忆、不产生半成品行程（FR-508、UF-05.E3）。
4. 异常提示以文本表达，不只依赖颜色（NFR-303）。

## 四、关键状态机

### 4.1 会话状态（session）

```text
无会话 --(提交需求)--> 执行中
执行中 --(全部任务完成)--> 已完成
执行中 --(用户取消)--> 已取消
执行中 --(超时/重试耗尽/契约不匹配)--> 已失败
执行中 --(成本触顶)--> 已失败（原因：成本上限）
已完成 --(修改约束重跑)--> 执行中
已失败 --(用户重试)--> 执行中
```

状态约束：

- 「已取消」与「已失败」均不得残留记忆写入或行程变更（FR-508）。
- 「已失败」必须携带失败环节与影响范围（AB-06）。
- 「执行中」不阻断其他页面导航（导航约束第 2 条）。

### 4.2 Agent 任务状态（agent task）

```text
等待 --(依赖满足)--> 执行中
等待 --(前置失败且不可跳过)--> 跳过
执行中 --(产出符合契约)--> 完成
执行中 --(超时/错误/契约不匹配)--> 失败
失败 --(重试未超上限)--> 执行中
```

状态约束：

- 契约不匹配按失败处理（PRD 6.5 约束）。
- 「跳过」需在工作室中说明跳过原因，不可静默省略（FR-504、AB-06）。

### 4.3 行程节点状态（trip item）

```text
草稿 --(用户确认)--> 已确认
已确认 --(用户锁定)--> 已锁定
已锁定 --(用户解锁)--> 已确认
已确认 --(重新规划)--> 草稿（可被 Agent 调整）
已锁定 --(重新规划)--> 已锁定（Agent 不得修改）
任意状态 --(用户删除)--> 已移除
```

### 4.4 记忆条目状态（memory item）

```text
不存在 --(用户明确表达)--> 明示记忆
不存在 --(行为推断)--> 推测记忆
推测记忆 --(用户确认)--> 明示记忆
推测记忆 --(用户否认)--> 已删除
明示记忆 --(用户编辑)--> 明示记忆（更新时间刷新）
任意状态 --(用户删除或清空)--> 已删除
```

状态约束：

- 推测记忆只影响排序，不可作为硬性约束（FR-307）。
- 忌口类记忆一律为硬性约束（FR-308）。
- 系统写入或状态变更必须可感知且可撤销（FR-306）。
