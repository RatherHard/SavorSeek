# SavorSeek 验收标准

## 一、文档说明

### 1.1 文档目的

本文档把 [`PRD.md`](PRD.md) 的需求条目和 [`用户流程.md`](用户流程.md) 的流程步骤转换为可判定的验收条件，作为 MVP 提测、评审和发布准入的唯一判据。

每条验收标准都必须能被一次明确的操作或一次自动化测试判定为通过或失败。无法判定的描述不写入本文档，改记入 PRD 未决问题。

### 1.2 关联文档

| 文档 | 关系 |
|------|------|
| [`PRD.md`](PRD.md) | 上游：需求编号（FR / NFR / AB）来源 |
| [`用户流程.md`](用户流程.md) | 上游：流程步骤编号（UF）来源 |
| [`docs/项目计划书.md`](../项目计划书.md) | 上游：第十一章质量与验收指标 |

### 1.3 编号与结构

验收条目使用 `AC-<模块段><序号>`，与需求编号段对应：

| 编号段 | 范围 | 对应需求 |
|--------|------|----------|
| AC-1xx | 账户与个人设置 | FR-1xx |
| AC-2xx | 地图与地点探索 | FR-2xx |
| AC-3xx | 长期记忆 | FR-3xx |
| AC-4xx | 多来源信息整合 | FR-4xx |
| AC-5xx | Agent 编排与工作室 | FR-5xx、AB-xx |
| AC-6xx | 推荐与解释 | FR-6xx |
| AC-7xx | 行程规划 | FR-7xx |
| AC-8xx | 反馈与纠错 | FR-8xx |
| AC-9xx | 非功能与降级 | NFR-xxx |

每条包含：编号、验收条件（Given / When / Then）、关联需求、优先级、验证方式。

### 1.4 验证方式定义

| 标记 | 含义 | 说明 |
|------|------|------|
| U | 单元测试 | 领域逻辑、约束解析、排序、状态机 |
| I | 集成测试 | 数据访问、RLS、Edge Function、Agent 契约 |
| E | 端到端测试 | 真实流程串联，覆盖 NFR-402 指定流程 |
| M | 人工验证 | 需要人工判断的体验、可访问性、文案 |
| T | 工具检测 | 静态扫描、性能与对比度测量工具 |

一条验收条目可有多种验证方式，至少一种为自动化（U / I / E）时方可计入自动化覆盖率统计。

### 1.5 缺陷严重级别

| 级别 | 判定 | 处置 |
|------|------|------|
| 阻断 | 违反合规红线、私有数据泄露、硬性约束被违反、静默写入记忆或行程 | 阻断发布，必须修复 |
| 严重 | P0 验收条目不通过 | 阻断发布 |
| 一般 | P1 验收条目不通过，或存在未标注的降级 | 可带缺陷发布，需记录降级说明 |
| 轻微 | 文案、非关键视觉、P2 相关 | 记录并排入后续迭代 |

## 十一、MVP 发布准入清单

发布前逐项确认，任一项未通过即不发布。

### 11.1 功能准入

- [ ] 全部 P0 验收条目通过，无阻断与严重缺陷
- [ ] 用户可完成 UF-01 至 UF-08 的完整流程
- [ ] 推荐结果对忌口、预算、时间窗、区域、开放状态五类硬性约束零违反（AC-601）
- [ ] 记忆的查看、修改、删除、清空全部可用且真实生效（AC-304 ~ AC-307、AC-106）
- [ ] 行程调整后地图与时间表一致，锁定节点未被修改（AC-704 ~ AC-709）
- [ ] 全部外部信息带来源与更新时间标注（AC-401、AC-207）

### 11.2 体验准入

- [ ] 新用户从启动到得到一次可执行的美食安排，无阻塞性卡点（UF-01 → UF-03 → UF-04）
- [ ] 长耗时任务全程有阶段进度，无「疑似无响应」区间（AC-903、AC-904）
- [ ] 每条推荐均有可理解的理由（AC-603）
- [ ] 常见异常场景均给出可操作的降级结果并显式标注（AC-911 ~ AC-917）

### 11.3 非功能准入

- [ ] 性能指标 AC-901 ~ AC-906 全部达标
- [ ] 可访问性 AC-921 ~ AC-928 全部达标
- [ ] 安全合规 AC-931 ~ AC-939 全部达标，密钥扫描无发现
- [ ] 覆盖率不低于 80%，端到端套件覆盖六个关键流程（AC-941、AC-942）

### 11.4 合规红线复核

以下任一项不通过，直接判定为阻断级缺陷：

- [ ] 无未授权的内容抓取（AC-937）
- [ ] 无私有数据跨用户泄露（AC-102、AC-931）
- [ ] 无硬编码密钥（AC-932、AC-933）
- [ ] 无静默写入记忆或修改行程（AC-306、AC-509、AC-805）
- [ ] 无医疗或营养诊断类输出（AC-513）
- [ ] 无对营业状态、价格、排队的绝对承诺（AC-939）

## 十二、验收执行说明

1. **执行顺序**：先跑自动化（U → I → E），再执行工具检测（T），最后人工验证（M）。自动化未通过时不进入人工验证。
2. **缺陷记录**：每条失败需记录验收编号、实际表现、复现步骤与严重级别。
3. **降级发布**：仅当失败项全部为一般或轻微级别时允许带缺陷发布，且必须在 `docs/开发日志.md` 中记录降级说明与后续计划。
4. **需求变更**：需求变更须同步更新 [`PRD.md`](PRD.md)、[`用户流程.md`](用户流程.md) 与本文档三者的编号与版本历史，避免编号漂移。
