# 短期开发计划（单周迭代）

本文档规划 2026-08-24 起一周的开发工作。计划范围与优先级依据仓库当前的真实代码状态，而非文档中的目标状态。

## 一、迭代目标

**主目标：打通「在地图上找到一家店 → 看详情 → 加入行程」的最小闭环。**

这是当前唯一横跨地图、数据库与行程三个已有模块的用户可感知路径，也是多处缺口的共同根因。次目标为 Agent 侧骨架，仅在主目标验证通过后开工。

## 二、为什么选这条主线

### 2.1 现状盘点

| 模块 | 实际状态 | 依据 |
|------|----------|------|
| 客户端骨架 | 三页导航、主题、依赖注入已就绪 | `lib/app/` |
| Supabase 读写链路 | 已打通并实测，50 项测试通过 | `docs/develop/2.前端与Supabase对接.md` |
| 行程数据模型 | 4 表 9 函数 3 策略已应用 | `supabase/migrations/` |
| 地图 | 仅底图与手势，无标记、无检索、无选点 | `lib/features/explore/amap_surface.dart:11` |
| 地点数据 | **无 `places` 表**，`trip_items.place_id` 是无引用目标的裸 uuid | `20260821000002_itinerary_schema.sql:59` |
| 写入 UI | RPC 已封装，但入口为空实现 | `lib/features/trip/trip_page.dart:238,365` |
| 指令栏 | 组件支持 `onSubmit`，但 `ExplorePage` 未传入，按钮恒禁用 | `explore_page.dart:44` |
| Agent 编排 | 23 行占位，返回固定 JSON；无任何 agent 表 | `supabase/functions/agent/index.ts` |
| 共享契约包 | 三个包仅有 `.gitkeep` | `packages/` |

### 2.2 排序理由

**为什么先做地点而不是先做 Agent。** 文档已定义 8 角色、12 命令、23 事件的完整契约，但 Agent 的每一条工具调用（`search_places`、`get_place_details`、`create_trip_draft`）都以地点数据为输入或输出。地点层缺失时，Agent 编排只能返回构造数据，实现出来无法验证，且契约会在真实数据接入后返工。这与设计文档「每个阶段先稳定契约和测试」的建议一致。

**为什么 `places` 是关键路径。** 地图无标记、地点详情无处可点、`place_id` 悬空、收藏与对比无落脚点——这些是同一个缺口的不同表现。补上这张表可一次性解锁多项。

**为什么把未部署的迁移放在第一天。** `20260823000004_itinerary_conflict_errcode.sql` 修正 revision 冲突错误码，未部署前所有并发写入路径的失败行为都是错的（504 而非可处理的冲突）。本周所有写入功能都建立在这条修正之上，不能带着未验证的前提往上叠。

**Agent 侧为什么只搭骨架。** 一周内做不完 8 角色 12 命令。骨架的价值在于用真实的会话/指令/任务表验证「非聊天式交互」这一产品形态假设（验收标准 AC-AS-001~003），并让指令栏从禁用变为可用。真实编排留到地点与推荐契约稳定之后。

## 三、任务清单

### D1：清理既有前提（半天）

| # | 任务 | 验收标准 |
|---|------|----------|
| 1.1 | 部署 `20260823000004` 迁移到自建实例 | 并发写入返回 `P0002` 而非 504，客户端映射到 `conflict` 分支 |
| 1.2 | 清理联调残留（2 个行程 + 1 个测试账号） | 直连数据库删除，`trips` 表仅余预期数据 |
| 1.3 | 服务端配置 HTTPS 或明确本周维持 HTTP | 若配好，移除 Android `usesCleartextTraffic` 与 iOS ATS 例外；若不配，在本文档标注为「已知开发期妥协」 |

任务 1.3 的两种结果都可接受，但必须显式决策，不能默认拖延——它决定后续是否需要为 Web 服务 Key 的传输额外设防。

**决策（2026-08-23）：维持 HTTP，标注为「已知开发期妥协」。** 服务器无域名、未装 nginx/caddy/certbot，仅开放 8000/HTTP，配置 HTTPS 会占去 D1 半天以上。保留 Android `usesCleartextTraffic` 与 iOS ATS 例外。风险边界：高德 Web 服务 Key 只存服务端环境变量、绝不下发客户端，因此明文信道上不会泄漏该 Key；真正暴露的是用户 JWT。此妥协仅在开发期成立，公开发布前必须配置 HTTPS。

### D1–D2：`places` 表与 POI 代理（1.5 天）

| # | 任务 | 验收标准 |
|---|------|----------|
| 2.1 | 新增迁移建 `places` 表：`id`、`provider`、`provider_place_id`、`name`、`category`、`address`、`location`（gcj02 经纬度）、`raw`、`fetched_at`、`updated_at` | `(provider, provider_place_id)` 唯一；`trip_items.place_id` 加外键指向 `places.id` |
| 2.2 | `places` 的 RLS 与授权 | 全体 `authenticated` 可 `select`（地点是公共数据，非用户私有）；DML 全部 revoke，仅 `security definer` 函数可写 |
| 2.3 | Edge Function `places-search`：代理高德 Web 服务 API `/v3/place/text` 与 `/v3/place/around` | 校验 JWT；命中缓存（`fetched_at` 在 TTL 内）直接返库内结果，未命中则请求高德并 upsert |
| 2.4 | Web 服务 Key 注入 | Key 存服务端环境变量，**绝不下发客户端**；缺失时函数返回明确错误而非空结果 |

**任务 2.3「校验 JWT」的实现前提（2026-08-23 实测修正）**：不能依赖平台配置，必须写在函数代码里。自建实例的 Kong 上挂的是 `key-auth + acl`，校验的是随客户端分发的 anon key（代表「未认证访客」身份），并不校验用户 JWT；`config.toml` 的 `verify_jwt` 只对 CLI 的本地 `functions serve` 生效，而 edge-runtime 的 `VERIFY_JWT` 环境变量对 main 服务无效。若不在函数内显式校验，任何持有 anon key 的人都能免登录消耗高德配额。已改为在函数内用 `auth.getUser()` 校验。

**技术说明（需修正一处认知）**：`amap_map 1.0.15` 官方插件只提供地图显示（`AMapWidget`），**不含 POI 搜索能力**。因此检索走 Edge Function 代理高德 Web 服务 API，而非客户端 SDK。这一路径反而更契合「服务端缓存」目标：Key 不进客户端、配额可控、结果天然落库。

坐标系必须统一为 `gcj02`，与地图底图及 `place_snapshot` 的 `coordinate_system` 约束一致，避免出现偏移。

### D3–D4：地图标记与地点详情（2 天）

| # | 任务 | 验收标准 |

## 四、本周明确不做

| 项 | 理由 |
|----|------|
| Realtime 事件订阅、去重、断线恢复 | 属设计文档阶段二；任务表尚未稳定前接入会返工 |
| LangChain 多 Agent 真实编排 | 依赖地点与推荐契约稳定 |
| `packages/contracts` 共享契约包 | 契约字段本周仍在变动，过早固化即返工。表结构稳定后再抽取 |
| 长期记忆、内容平台接入 | 属阶段五，且内容授权边界需先确认 |
| 收藏、地点对比、路线规划 | 依赖本周的 `places` 表，下一迭代 |
| 跨时区行程展示 | 已记录为遗留项，非本周闭环阻塞项 |
| 虚拟人物形象与动画 | OQ-AS-006 决定先用静态形象，不是本周瓶颈 |

## 五、风险与应对

| 风险 | 影响 | 应对 |
|------|------|------|
| 高德 Web 服务 API 需单独申请 Key 与配额 | 阻塞 2.3、3.2 | D1 先申请。未到位时用固定种子数据（10~20 条大连本地店）跑通 UI 与 `places` 表，检索层后补 |
| 高德 POI 数据的缓存与二次分发受服务条款约束 | 合规风险 | 仅缓存展示必需字段，保留 `provider_place_id` 可溯源，不做批量导出；边界不清时按最小缓存处理 |
| `place_id` 加外键可能与既有测试数据冲突 | 迁移失败 | 依赖任务 1.2 先清理残留数据 |
| 服务器 3.6Gi 内存已用 1.5Gi | 新增 Edge Function 可能触发 OOM | 部署后观察 `docker stats`；已有 2G swap 作缓冲 |
| HTTP 明文下 Web 服务 Key 经函数中转 | Key 本身不下发，风险有限 | 但 JWT 仍明文，故任务 1.3 应尽量选 HTTPS |
