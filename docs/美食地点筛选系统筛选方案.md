# 美食地点筛选系统筛选方案

## 1. 文档说明

本文说明 SavorSeek 当前美食地点筛选系统的实际实现方案，覆盖地图视野计算、地点候选过滤、结果批次管理、地图标记空间筛选、结果抽屉展示以及异常和边界处理。

本文描述的是当前代码行为，不等同于未来规划中的完整筛选能力。当前方案的主要目标是：

- 只在地图上展示符合餐饮类别且具备有效坐标的地点；
- 地图标记在当前屏幕可观测区域内尽量分散，避免高评分地点集中在同一块区域；
- 结果抽屉保留适合列表查看的餐饮地点，包括没有坐标或评分的地点；
- 地图移动后使用当前视野检索结果，避免继续使用过期的关键词检索批次；
- 在地点重复、结果过期、请求失败和无效视野等情况下保持确定性和可恢复性。

## 4. 地图视野计算

### 4.1 实际地图尺寸

探索页使用 `LayoutBuilder` 获取地图区域的实际 `width` 与 `height`。底部 Agent 指令栏不计入地图尺寸，因此筛选计算只针对地图所在的 `Expanded` 区域。

关键代码：

- `apps/mobile/lib/features/explore/explore_page.dart`
  - `_onMapSizeChanged`
  - `_scheduleViewportSearch`
  - `_refreshMarkerSelection`
- `apps/mobile/lib/features/explore/map_viewport.dart`
  - `buildMapViewportQuery`

生产环境不使用固定的手机尺寸。测试中出现的 `360 × 640` 只是测试上下文，不是生产筛选参数。

### 4.2 视野半径估算

由于当前地图插件没有可稳定依赖的 visible-region API，系统不直接读取精确的四角经纬度，而是使用相机中心、缩放级别和地图尺寸估算一个足够覆盖视野的圆形半径。

计算过程如下：

1. 根据中心纬度和 zoom 计算 Web Mercator 的 `metersPerPixel`：

```text
metersPerPixel =
  156543.03392 × cos(latitude) ÷ 2^zoom
```

2. 计算地图区域对角线的一半：

```text
cornerPixels = sqrt(width² + height²) ÷ 2
```

3. 乘以 1.25 的保守系数，得到估算半径：

```text
estimatedRadius = cornerPixels × metersPerPixel × 1.25
```

4. 将半径限制在 `1` 到 `50,000` 米之间。

该方案优先保证不漏掉视野边缘地点，但由于它是圆形近似，不代表高德返回结果严格等于屏幕矩形范围。客户端在收到结果后还会进行一次投影矩形裁剪。

### 4.3 查询去抖和去重

地图相机停止移动后不会立即逐帧请求：

- 使用约 `400ms` 去抖；
- 只有地图实际尺寸有效时才发起查询；
- 使用归一化 `queryKey` 避免相同视野重复请求；
- 请求参数包括中心点、zoom、半径、地图宽高；
- 关键词检索和视野检索使用请求序号丢弃过期响应。

## 5. 地点候选过滤

地图 marker 与结果抽屉采用不同的过滤规则。

### 5.1 餐饮类别识别

`isFoodCategory` 对高德类别串进行以下归一化：

- 将全角分号 `；` 转换为半角分号 `;`；
- 按分号拆分多级类别；
- 去除每一级前后的空白；
- 使用不区分大小写的比较；
- 只要任一级命中餐饮类别集合，即判定为餐饮地点。

当前餐饮类别集合包括：

```text
餐饮服务、餐饮、中餐厅、西餐厅、外国餐厅、快餐厅、
特色餐饮、火锅、烧烤、小吃、咖啡厅、茶饮、甜品、
糕点、面包、料理
```

### 5.2 地图 marker 候选资格

`selectMapMarkers` 的自动 marker 候选必须满足：

- 地点 ID 去除空白后非空；
- 类别命中餐饮类别；
- 纬度与经度同时存在；
- 纬度和经度均为有限数值；
- 纬度在 `-90` 到 `90` 之间；
- 经度在 `-180` 到 `180` 之间。

当前实现不会因为评分缺失而直接排除地点。评分缺失、`NaN` 或超出正常范围的地点仍可以作为地图候选，但在排序时被视为低优先级。结果抽屉同样允许展示没有评分的餐饮地点。

### 5.3 结果抽屉过滤

结果抽屉使用 `filterFoodPlaces`，只检查餐饮类别，不要求：

- 有效坐标；
- 有效评分；
- 能够落在当前地图视野内。

因此，地点可能出现在结果抽屉中，但不一定生成地图 marker。例如：

- 没有坐标的地点保留在列表中，不能落点；
- 没有评分的地点保留在列表中，评分信息缺失不影响基础地点浏览；
- 地图视野外地点可作为当前关键词结果保留在抽屉中。

## 6. 候选去重与质量排序

### 6.1 地点去重

候选在地图筛选前按地点 ID 去重。相同 ID 只保留一条记录，优先级由 `_compare` 决定。

去重和排序的稳定比较顺序为：

1. 有效评分降序；
2. 到当前地图中心的投影距离升序；
3. 去空白后的地点 ID 升序；
4. 经度升序；
5. 纬度升序；
6. 地点名称升序；
7. 类别升序；
8. 地址升序；
9. 抓取时间升序。

这样可以在输入顺序变化时保持输出稳定，也可以在同一地点 ID 出现多个版本时优先保留质量更高的记录。

### 6.2 评分优先级

有效评分范围为 `0` 到 `5`，包括边界值。有效评分参与质量排序：

- `5.0` 优先于 `4.0`；
- 相同评分时比较距离和稳定标识；
- 缺失或异常评分作为低优先级处理。

评分是网格内的质量决策因素，但不能单独决定整个视口的 marker 名额。空间覆盖优先级会阻止高评分密集区域垄断所有 marker。

## 7. 当前视野裁剪与投影

### 7.1 局部屏幕坐标

地点经纬度会被转换为相对于地图中心的近似屏幕像素坐标：

```text
x = 经度差 × 每度经度米数 × cos(中心纬度) ÷ metersPerPixel
y = 纬度差 × 每度纬度米数 ÷ metersPerPixel
```

经度差会进行日期变更线归一化：

- 大于 `180°` 时减去 `360°`；
- 小于 `-180°` 时加上 `360°`。

因此中心点接近 `180°` 时，`-179.x°` 的地点会被当作邻近地点，而不是被误认为相距接近整个地球周长。

### 7.2 视野矩形

投影点需要落在以下范围内才会进入当前地图候选：

```text
|x| ≤ width ÷ 2 + viewportPaddingPx
|y| ≤ height ÷ 2 + viewportPaddingPx
```

默认 `viewportPaddingPx` 为 `20`，用于降低边界处因估算误差造成的闪烁或漏选。

这一步只决定地点是否位于估算的可见矩形内，不负责决定最终 marker 数量。

## 8. 目标 marker 数量

### 8.1 配置项

当前默认配置如下：

| 配置项 | 默认值 | 作用 |
|------|------:|------|
| `markerFootprintPx` | 40 | marker 可读占用的近似像素尺寸 |
| `markerGapPx` | 8 | marker 之间的目标间距 |
| `viewportPaddingPx` | 20 | 视野边界缓冲 |
| `minMarkers` | 4 | 默认期望的最低数量下限 |
| `maxMarkers` | 20 | 单次最多展示数量 |
| `minDensityFactor` | 0.5 | 视口密度下限 |

### 8.2 容量计算

首先计算基于 marker 占用尺寸的行列容量：

```text
cellSize = markerFootprintPx + markerGapPx
columns = floor(width ÷ cellSize)
rows = floor(height ÷ cellSize)
capacity = floor(columns × rows × density)
```

`density` 综合以下因素：

- zoom 越高，允许的展示密度越高；
- 查询半径越小，允许的展示密度越高；
- `metersPerPixel` 越小，地图越近，允许的展示密度越高；
- 最终密度不低于 `minDensityFactor`。

当前 `targetCount` 是实际可达到的数量上限，最终不超过：

- 当前视野候选数量；
- `maxMarkers`；
- 根据地图宽高和密度计算出的容量。

如果可见候选很少，或地图空间容量不足，实际 marker 数量可以少于默认的 `minMarkers`，不会为了满足最低数量而强行重叠。

## 9. 视口网格分散选择

### 9.1 问题背景

旧的选择方式按“评分最高 → 距离最近”的全局顺序遍历候选。即使候选分处不同区域，高评分地点集中在某个街区时，也可能先占满全部 marker 名额，导致其他可见区域没有代表点。

当前实现改为“先空间覆盖、再质量回填”。

### 9.2 建立视口网格

网格列数和行数根据目标 marker 数量以及地图宽高比计算：

```text
aspect = width ÷ height
columns ≈ round(sqrt(targetCount × aspect))
rows = ceil(targetCount ÷ columns)
```

列数和行数还会受到地图实际可容纳列数、行数的限制，单个网格不会被配置成超过基础 marker 容量的大小。

### 9.3 候选归桶

每个已经通过视野裁剪的地点，根据其投影坐标归入网格：

```text
xCell = floor(((x + width ÷ 2) ÷ width) × columns)
yCell = floor(((y + height ÷ 2) ÷ height) × rows)
```

边界值会被限制在最后一列或最后一行，避免右边界和下边界产生越界网格。

### 9.4 每个网格选择代表地点

网格按固定的行优先顺序遍历。每个网格内的候选仍按 `_compare` 排序，并选择该网格中最优且不违反 marker 间距的地点。

这个过程带来两个保证：

1. 一个密集区域不会仅凭高评分占据全部名额；
2. 只要其他区域存在可用候选，它们会在首轮获得代表点的机会。

因此，结果是“趋于均匀分布”，而不是数学意义上的严格均匀分布。真实地点分布稀疏时，空网格不会被虚构地点填充。

### 9.5 严格间距回填

首轮网格选择后，如果仍未达到目标数量，系统从未选候选中按全局质量顺序回填：

- 每个候选必须与已有 marker 保持严格间距；
- 违反间距的候选跳过；
- 回填直到达到目标数量或没有候选满足条件。

严格间距默认使用：

```text
markerFootprintPx + markerGapPx
```

### 9.6 宽松间距回填

若严格间距回填后仍有空余名额，系统会进行最后一轮宽松回填：

```text
fallbackSpacing = max(8px, (markerFootprintPx + markerGapPx) × 0.2)
```

宽松回填仍然拒绝相同地点 ID，并继续检查候选之间的距离。该阶段是为了在地点高度密集时保留更多可操作地点，但可能产生较明显的视觉拥挤，因此不应理解为完整的无重叠保证。

## 10. 地图候选与抽屉候选分离

### 10.1 `visiblePlaces`

`visiblePlaces` 服务于结果抽屉。手动关键词检索后，关键词结果继续优先用于列表展示，自动视野刷新不会静默替换用户正在浏览的关键词结果。

### 10.2 `mapPlaces`

`mapPlaces` 服务于地图 marker：

- 当前存在成功的视野检索结果时，优先使用 `_viewportResult`；
- 没有视野结果时，回退到 `visiblePlaces`。

这样可以避免以下问题：

```text
用户先搜索“烧烤”
        ↓
关键词地点集中在某个区域
        ↓
用户拖动地图到另一个区域
        ↓
新的 around 检索成功
        ↓
地图 marker 使用新的视野结果
结果抽屉仍保留关键词结果语义
```

### 10.3 请求失败时的行为

视野请求失败时：

- 控制器保留之前成功的视野结果；
- 地图不会因为一次失败而清空已有 marker；
- 当前失败请求的中心、半径和关键词会被记录；
- 点击重试时复用失败请求的参数，而不是错误地使用上一次成功请求的位置。

## 11. 服务端候选来源

### 11.1 高德请求

地点检索通过 Supabase Edge Function 代理高德 Web Service API，客户端不直接持有高德 Web Service Key。

around 请求包含：

- 经度和纬度；
- 检索半径；
- 可选关键词；
- 页码；
- `extensions=all`，用于取得商业扩展中的评分字段。

### 11.2 当前候选数量限制

高德单页请求使用 `PAGE_SIZE = 20`。当前客户端的 `searchAround` 接口没有暴露分页参数，因此自动视野检索实际使用第一页候选。

这意味着：

- 客户端空间分散算法只能在返回的候选中进行分散；
- 如果高德第一页本身已经偏向某个区域，客户端无法从未返回的区域补充地点；
- 多页合并、网格分区请求和更完整的空间覆盖属于后续增强，不属于当前筛选算法本身。

服务端缓存会按检索类型、中心点、半径、页码、关键词和响应契约版本构造查询键，并保留高德结果顺序。

## 12. 状态与异常处理

### 12.1 无效筛选上下文

如果出现以下任一情况，地图 marker 选择返回空结果并标记为无效：

- 中心纬度或经度不是有限值；
- 中心坐标越界；
- zoom 不是 `0` 到 `24` 范围内的有限值；
- 地图宽高不是正数；
- `metersPerPixel` 不是正的有限值；
- 查询半径不是正的有限值；
- marker 配置不合法。

### 12.2 空结果

空结果表示当前检索没有符合条件的地点，与服务失败区分处理：

- 保留地图底图；
- 结果抽屉不显示虚构地点；
- 用户可以修改关键词或扩大范围。

### 12.3 请求失败

服务端配置错误、未认证、网络错误、上游不可用和存储失败使用不同的失败类型。用户界面根据失败类型决定是否显示重试入口。

配置类错误不会显示无意义的重试按钮；网络、配额和上游暂时不可用等错误可以重试。

## 13. 确定性与性能约束

当前方案遵循以下约束：

- 不依赖输入候选的原始顺序；
- 不依赖 `Set` 的迭代顺序决定地点优先级；
- 相同输入和相同视野应产生相同 marker 选择结果；
- 选择结果使用版本化 `selectionKey` 缓存；
- marker 只有在选择结果实际变化时才重新构造；
- 地图移动过程中不逐帧请求；
- 地图组件 `AmapSurface` 不负责业务过滤，只渲染上层传入的 marker；
- 地图选择逻辑保持为纯 Dart 逻辑，便于单元测试且不依赖原生地图 SDK。

## 14. 已验证行为

当前自动化测试覆盖以下行为：

- 餐饮类别识别和结果抽屉过滤；
- 无坐标餐饮地点保留在抽屉；
- 无评分和异常评分地点仍可作为低优先级地图候选；
- 非餐饮地点不进入地图 marker 候选；
- 无效坐标被排除；
- 相同地点 ID 去重并保留更高质量记录；
- 高评分地点集中时，marker 覆盖多个可见区域；
- 密集地点的严格间距和宽松回填；
- 动态目标数量与最大 marker 数量；
- 候选输入顺序变化时结果保持稳定；
- 关键词结果与视野结果分别服务抽屉和地图；
- 视野请求参数被正确传递；
- 相同视野 query key 不重复请求；
- 过期响应不会覆盖较新的检索结果；
- 无效地图尺寸和 zoom 不会导致异常。

## 15. 当前限制与后续方向

### 当前限制

1. 视野边界是基于相机中心和地图尺寸的保守估算，不是地图 SDK 提供的精确可见多边形。
2. 地点投影使用局部近似坐标，而不是完整的瓦片世界像素投影。
3. 高德自动视野检索当前只取得第一页候选，候选多样性受服务端返回顺序影响。
4. 宽松间距回填可能造成 marker 视觉拥挤。
5. 结果抽屉有底部抽屉遮挡地图区域，当前筛选计算未根据抽屉展开高度动态缩减地图有效区域。
6. 当前没有菜系、价格、距离、营业状态、预算和用户偏好等复杂筛选条件。

### 后续方向

- 在地图插件提供稳定能力后，改用精确 visible-region 或 bbox 查询；
- 使用与瓦片地图一致的 Web Mercator 世界像素投影；
- 对 around 查询增加受控的多页或分区检索，并单独维护 marker 候选池；
- 引入真正的 marker 聚合，展示聚合数量并支持点击展开；
- 根据底部抽屉实际遮挡区域调整 marker 有效视口；
- 增加菜系、价格、距离、评分、营业状态和预算筛选；
- 将用户收藏、口味记忆和 Agent 任务结果接入候选排序，但继续保留空间覆盖约束；
- 通过真机和模拟器验证不同屏幕尺寸、缩放级别、日期变更线和高纬度区域的视觉效果。
