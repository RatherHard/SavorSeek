# SavorSeek 项目介绍讲稿

---

## 开场：我们真正想解决的，不是“搜不到餐厅”

大家好，今天我想介绍的项目叫 **SavorSeek**。
当我们第一次来到一座陌生城市，想认真体验当地美食时，通常会同时打开地图、点评软件、短视频平台和自己的收藏夹。我们会看到很多“必吃榜”“本地人才知道的小店”和“排队两小时也值得”的推荐，但信息越多，做决定反而越困难。

我们真正需要回答的，往往不是“附近有哪些餐厅”，而是：

- 哪一家真的适合我的口味？
- 它是否符合我的预算、时间和交通方式？
- 网上的信息是不是已经过时？
- 中午吃完这一家，下午茶和晚餐应该怎么安排？
- 几家店之间能不能形成一条真正走得通的路线？
- 我过去收藏过、喜欢过或明确不喜欢的东西，能不能在下一次旅行中继续发挥作用？

所以，SavorSeek 并不想再做一个简单的餐厅搜索工具。

我们想解决的是一个更完整的问题：

> **如何把分散在地图、内容、用户偏好和旅行约束中的信息，转化成一份用户看得懂、改得动、真正走得通的美食旅行计划。**

---

## SavorSeek 的核心理念

SavorSeek 的核心理念可以概括成一句话：

> **地图负责呈现真实空间，Agent 负责理解用户需求，长期记忆负责让推荐越来越贴合用户。**

这三个部分并不是简单地叠加在一起，而是各自解决一个不同的问题。

### 1. 地图负责真实空间

> **这些地方在哪里，以及我应该怎样到达它们。**

### 2. Agent 负责理解和协作

> **用户不是在和一个机器人聊天，而是像队长一样，指挥一支分工明确的 Agent 小队。**

例如，这支小队中可以有：

- **需求分析员**：理解预算、时间、菜系、忌口和交通方式；
- **地图侦察员**：在目标区域内寻找合适的地点；
- **口味顾问**：结合用户过去的选择判断个人偏好；
- **内容研究员**：整理公开许可或授权来源中的探店信息；
- **事实核验员**：检查地址、营业时间以及信息是否存在冲突；
- **推荐顾问**：筛选候选，并解释为什么推荐；
- **路线规划员**：把地点放入具体日期和时段，形成行程草案；
- **队务官**：协调其他成员，并把关键进展汇报给用户。

这里真正重要的，并不是多放几个卡通角色，而是把搜索、核验、筛选和规划这些原本混在一起的过程，拆成一个**可观察、可解释、可控制**的协作过程。

用户能够看到谁正在做什么、找到了多少候选、哪些信息仍不确定，以及现在需要自己做什么决定。

### 3. 长期记忆负责持续理解

普通推荐系统经常需要用户一次次重复说明：“我不太吃甜”“我更喜欢本地小店”“我可以多走一点路，但不想长时间排队”。

SavorSeek 希望把真正有价值的偏好沉淀下来，例如：

- 喜欢哪些菜系和口味；
- 更偏爱老字号、街边小店还是精致餐厅；
- 对价格、距离和排队时间的容忍度；
- 去过、收藏、喜欢或不喜欢的地点；
- 在不同城市和旅行场景下的临时偏好。

---

## 结尾

SavorSeek 最终想做的，不是替用户选择一家评分最高的餐厅，也不是让用户在旅行中多使用一个聊天机器人。

我们希望它能够理解：一个人为什么喜欢某类味道，愿意为哪种体验多走一点路，对预算、排队和信息真实性又有怎样的要求；然后把这些偏好放回真实地图和有限的旅行时间中，形成一份真正可以执行的计划。

> **地图保证真实，Agent 提供协作，记忆建立长期理解，而最后的决定始终留在用户手中。**

这就是 SavorSeek 的核心 Idea：

> **让每一次美食旅行，从分散的信息搜索，变成一场由用户掌舵、由 Agent 小队协助完成的地图探索。**
